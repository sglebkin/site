# Website papers and CV

This repository is the existing static website at https://sglebkin.com, published from `master` in `sglebkin/site` through GitHub Pages. Preserve its existing design and publishing setup.

- Add or update the requested paper PDF and its website entry. Use the requested filename and the title, authors, and abstract from the actual paper.
- Keep the research listings in `index.htm` and `huindex.htm` consistent.
- On both homepages, keep the paper title linked directly to its PDF, the coauthors on a separate visible line, and a separate collapsible `Abstract` line. At the end of the expanded abstract, put the `BibTeX and more` link after a single `<br>` in the same paragraph.
- Link coauthors' names to their current academic websites, including on the paper's landing page. Reuse and verify existing links; look up missing or outdated links. Prefer a personal academic site, or an official institutional profile when no personal site can be found. Stathi Avdis's existing link is https://apps.ualberta.ca/directory/person/avdis. Use Ji Shen's English profile: https://en.gsm.pku.edu.cn/faculty/jishen/.
- Create or update the paper's `BibTeX and more` landing page whenever adding a paper, replacing its PDF, or changing its title, authors, abstract, version date, or publication status. This includes inactive working papers. Follow the landing-page conventions below.
- Put newly posted or substantively revised working papers first. Renumber the working papers consecutively after publications, and apply the same order and numbering to the public CV. For example, with six publications, the most recently updated working paper is number 7 and the remaining working papers shift down. A link-only correction need not change the paper order.
- Update `CV.tex`, its last-updated date, and rebuild `CV.pdf` whenever adding or updating a paper. In the CV, coauthor names are plain text and paper titles link to their paper URLs. The public CV is PDF-only; the retired HTML CV is no longer maintained and should not be recreated.
- `CV.tex` also drives the local Faculty Activity Report edition. Keep `\new{...}` markers for report changes. Move a newly public paper out of `faronly`, while keeping other unpublished work in that block and its numbering consistent. `FAR_CV.tex` and `FAR_CV.pdf` are ignored local files and must remain uncommitted.
- Build the public CV with `latexmk -pdf -interaction=nonstopmode -halt-on-error -outdir=<temporary-directory> CV.tex`. Verify the rendered pages, paper links, ordering, numbering, and exclusion of remaining `faronly` material before replacing `CV.pdf`. If rebuilding the local FAR edition, use LuaLaTeX.
- When publishing is authorized, commit the requested site, landing-page, and CV changes, push through the existing GitHub Pages setup, and verify the affected live pages and PDF. A request to change this skill alone does not authorize publication.

## BibTeX and more pages

- Reuse the existing page and URL for each paper; use a root-level `.html` page for a new paper, alongside its PDF. Preserve existing PDF URLs. Use `chile.html` for the forthcoming layout and `fcie.html` for published citation fields, with the shared `main.css`, `citation.css`, and `citation.js`.
- Keep the page limited to a `Home` link, title, full author names with links, publication status, `This version: date`, a link labeled `PDF`, the full current abstract, and a `BibTeX` section with `Copy BibTeX`. Take the abstract and version date from the actual PDF or an explicit author correction. Show `Working paper` for inactive papers too; omit circulation history, inactive labels, and subsumed-by notes from these pages and their BibTeX.
- Put Google Scholar metadata in each dedicated page's HTML head, not on the homepage listing multiple papers: `citation_title`, a separate `citation_author` for each author, a verified numeric `citation_publication_date`, and an absolute `citation_pdf_url` pointing to the existing PDF. Maintain the canonical page URL and verified journal, DOI, volume, issue, and page metadata when applicable. Distinguish manuscript/version dates from journal publication dates; never put `forthcoming` in a date meta tag or infer a journal publication year from the draft date. Consult the [official Scholar inclusion guidance](https://scholar.google.com/intl/en/scholar/inclusion.html) when changing the metadata scheme.
- For working papers, use `@unpublished`, the verified manuscript year, and `note = {Working paper}`. For accepted journal articles whose publication year is unconfirmed, use `@article`, the journal name, and `year = {forthcoming}`, without a duplicate forthcoming note. For published articles, use verified publisher citation details and replace the forthcoming year when publication details become available. Set their BibTeX `url` to `https://doi.org/<DOI>` and retain the `doi` field; use the publisher's article page if no DOI exists. Working papers and forthcoming articles without a publisher DOI retain the website PDF URL in `url`. The visible `PDF` link and Scholar's `citation_pdf_url` continue to point to the website PDF.
- Check author names and order. Use ordinary braces for title fields, protecting acronyms or proper names where needed: `title = {{CHILE}}` preserves the acronym; avoid protecting the entire title unnecessarily.
- Verify the affected page's content, PDF and homepage links, metadata, and copied BibTeX. Check the rendered layout and Abstract control after layout changes, and compile changed BibTeX entries to catch formatting errors. Keep the abstract and citation readable without JavaScript and preserve the copy-button fallback.
